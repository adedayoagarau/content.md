# Promote UX-writing knowledge workflow

Use this workflow to move researched guidance into versioned core intelligence.

## Prerequisites

- Bounded source-position records with rights-safe synthesis.
- Conflict review across sources, repository contracts, and current governing evidence.

## Steps

### 1. Bound the claim

- [ ] Identify context, population, state, channel, locale, risk, and exceptions.
- [ ] Separate the documented source position from product interpretation.
- [ ] Reject copied prose and recognizable source examples.

### 2. Classify the knowledge

- [ ] Choose `hard`, `advisory`, `specialist`, `research`, `human_judgment`, or `preference`.
- [ ] Promote a hard rule only when independent governing or repository evidence supports it.
- [ ] Keep unobservable qualities as rubrics or research questions.

### 3. Encode and fixture

- [ ] Use only the closed declarative operator vocabulary.
- [ ] Declare required facts, applicability, unknown behavior, reason, consequence, and repair.
- [ ] Add original ordinary, adverse, missing-evidence, and non-applicable fixtures.

### 4. Review and release

- [ ] Review conflicts, false-positive risk, authority, privacy, and specialist boundaries.
- [ ] Record approval, version, migration, rollback, and retirement behavior.
- [ ] Publish an immutable rule-pack digest.

### 5. Monitor

- [ ] Measure false positives, false negatives, abstention usefulness, and reviewer agreement.
- [ ] Suspend or retire rules that exceed approved error bounds.
- [ ] Never promote use, preference, or generated output into training authority automatically.

## Exit criteria

- [ ] Rule lineage is complete and fixtures pass.
- [ ] Classification matches the evidence available to the runtime.
- [ ] The release is replayable, versioned, and reversible.
