# Structure and Navigation Checklist

Use this checklist before comparing stylistic or visual preferences.

## 1. Meaning and evidence

- [ ] Identify authoritative concepts, tasks, routes, states, and action effects.
- [ ] Identify required material information, options, rights, recovery, and remedies.
- [ ] Separate canonical meaning from layout and component expression.
- [ ] Record missing, conflicting, stale, or locale-specific evidence.
- [ ] Abstain when structure would invent a route, effect, option, or policy.

## 2. Task and temporal flow

- [ ] Define entry, orientation, prerequisites, action, consequence, completion, and exit.
- [ ] Provide current state or step for consequential multi-step tasks.
- [ ] Verify return and resumption behavior, including persistence and expiry.
- [ ] Connect blocked states to operable recovery or escalation.
- [ ] Avoid forcing repeated input the product can preserve.

## 3. Hierarchy

- [ ] Give every structural node a declared role and parent.
- [ ] Make the title identify page or task scope.
- [ ] Make each heading predict the section it introduces.
- [ ] Keep heading relationships meaningful without visual styling alone.
- [ ] Verify that ordering reflects task and decision needs, not internal ownership by default.

## 4. Navigation and choices

- [ ] Resolve each navigation item to a governed destination or effect.
- [ ] Preserve required alternatives, refusal, edit, undo, appeal, escalation, and exit routes.
- [ ] Record option provenance and ordering rationale where power or consequence is material.
- [ ] Distinguish global, local, task-progress, search, handoff, and recovery navigation.
- [ ] Verify external destinations, downloads, and state-changing actions are not misrepresented.

## 5. Links and labels

- [ ] Make labels predict their destination or effect.
- [ ] Avoid materially ambiguous duplicate labels within the defined scope.
- [ ] Use approved terminology consistently.
- [ ] Check link meaning outside immediate visual context.
- [ ] Confirm label, route, state, locale, and version remain aligned.

## 6. Progressive disclosure

- [ ] Keep facts that change the immediate decision in the visible decision path.
- [ ] Use disclosure for supporting explanation, examples, or optional depth.
- [ ] Ensure collapsed controls name the content or action they reveal.
- [ ] Preserve access when scripts, modes, viewports, or input methods differ.
- [ ] Test first use, repeat use, interruption, and adverse contexts.

## 7. Lists, tables, and structured presentation

- [ ] Use ordered lists only when sequence matters.
- [ ] Use unordered lists for comparable peers without implied order.
- [ ] Use tables only for meaningful row-column relationships.
- [ ] Declare headers, labels, grouping, order, and material relationships.
- [ ] Verify responsive, zoom/reflow, keyboard, screen-reader, and speech behavior with specialists.
- [ ] Provide an equivalent structure when the table or visual cannot preserve meaning in a supported mode.

## 8. Localization and evaluation

- [ ] Verify material destinations, choices, disclosures, and recovery remain equivalent across locales.
- [ ] Verify directionality, expansion, morphology, terminology, and jurisdiction with locale authority.
- [ ] Record deterministic results as `pass`, `fail`, `unknown`, or `not_applicable` with evidence.
- [ ] Test findability, interpretation, route choice, resumption, and task completion with intended populations.
- [ ] Compare brevity, scannability, rhythm, or visual elegance only after hard planes pass.

## Exit criteria

A decision-ready structure preserves canonical meaning, material choices, destination accuracy, temporal continuity, and supported-mode parity. Every route resolves, every action label predicts its effect, and specialist requirements are verified. Otherwise produce a finding, evidence request, or escalation rather than final presentation.
